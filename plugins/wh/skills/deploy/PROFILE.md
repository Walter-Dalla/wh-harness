# Profile of /wh:deploy

## Target
Public URL, where it runs (server, PaaS, region), who orchestrates (compose, Komodo, k8s, systemd), network and tunnel/proxy in front. Doc of the why: `docs/deploy.md`.

## Access
What the agent may touch: `no server access` (default) or the allowed command/MCP and its condition (owner confirmation on every call).

## Artifact
What gets published (image, package, bundle), registry (address, auth, insecure-registries), tags (`latest`, `sha-<commit>`, version), what goes inside and what stays out of CI (unversioned assets).

## Preconditions
One per line, with the command that checks it: tree committed in `<paths>`, daemon alive (`docker.exe version …`), registry reachable (`curl … /v2/` → 200/401), export templates, local assets. How to commit/push in this checkout (`_common § Git`).

## Publish
`<script> [version]`: what it does (tests, export, build, push), how long it takes, result lines to filter (`grep -E "…"`), re-push without rebuild when only the push failed.

## Update
Who (owner/agent) and how the target picks up the new artifact (button in the orchestrator, `pull && up -d`), where compose and env live on the target, how to pin a tag (`IMAGE_TAG=…`), ready signal (`healthy`).

## Verify
One per line: `curl … <URL>` → expected code and what it proves (site, API up, cache not stale). What never to call in production (rate-limited login, data creation). Logs the owner sends when it fails.

## Failures
Symptom → cause → action, one per line (502 from the proxy, `permission denied` on the socket, `HTTP response to HTTPS client`, `denied` on pull, web client broken by cache).

## Rollback
How to point the target at the previous tag, how to list tags, what is not a rollback (data volume).

## Backup
Backup command/cron, verification (`tail` of the log, one file per day), retention, off-host copy, restore rehearsal and real restore (confirmation; what never to run: `down -v`).

## Secrets
Target variables (name and where to obtain it, never the value), rotation (steps and window), credentials the agent never reads.

## External settings
Rules at the provider (DNS, CDN, WAF): what is on, what never to turn on and why.

## Extra clients
Builds distributed outside the target (desktop, mobile): export command, requirements (SDK, keystore), output.

## Initial setup
Steps for a server from scratch (the owner runs them), in order, with the date each was done.
