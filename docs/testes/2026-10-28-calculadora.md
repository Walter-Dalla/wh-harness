## What worked

- Whole flow with no intervention: profile → analysis → plan → items with commit and Acceptance → QA → fixes → retros → report → docs → cleanup → push. No `BLOCKED`.
- Profile generated with a source per line and honest `—` sections; run 2 skipped generation.
- Quality analysis and plan: alternatives with a why (manual parse × `argparse`, `x` × `*` in the shell), risks listed, executable Acceptance per item.
- Final QA in a worktree found 3 real bugs the implementer's suite did not catch (overflow, 4300 digits, `pow(2, 10**400)`); the retest found the neighbour. Bug/product-judgment triage respected: the judgment went to the report, not to the code.
- Retros in every agent, consolidated and deduplicated in the report; proposals cite the file and who applies them.
- Commits in the format (`<slug>-N:`, `QA-<lane>-NN:`, `docs:`, co-authorship), `.impl/` outside git, worktrees removed, clean `git status` at the end.
- No GitHub: both runs noticed, recorded it in the report title and gave the merge command.
- The project's hooks fired in every subagent and worktree (148 and 102 events): external observability works without changing the harness.
